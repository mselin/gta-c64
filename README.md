# Sleazeburg 64

A top-down crime satire for the browser, made to look and sound like a Commodore 64 game: 320×200 pixels,
16 colours, sprites and SID music. Play it at https://mselin.github.io/gta-c64/ .

A version for a real Commodore 64, in 6502 assembly, is being written in its own repository,
[mselin/Sleazeburg64](https://github.com/mselin/Sleazeburg64). Play it at https://mselin.github.io/Sleazeburg64/ .

The game is plain JavaScript modules with no build step. When a change reaches `main` and every check has passed,
CI publishes the game with GitHub Pages (see [The repository](#the-repository)).

## Run it locally

Browsers will not load modules from `file://`, so serve the folder:

```bash
npm start
```

Then open http://localhost:8064/ . Any static file server works just as well. To try Discord Rich Presence
on a copy served like this, start the bridge with `-allow-origin http://localhost:8064`.

## Tests

```bash
npm install
npx playwright install chromium
npm test
```

- `npm run test:unit` runs the logic tests in Node: maths helpers, city generation, playlist parsing, car
  handling, the heat system, and how people on foot look and get hit.
  It also includes a soak test: an hour of seeded, random play run without a browser, checking after every
  step that nothing has gone wrong (invalid numbers, a stuck player, runaway numbers of cars).
- `npm run test:e2e` plays the game in headless Chromium: starting, driving, police, jobs, the title-screen
  dialog, the radio and the information page. Requests to HVSC are answered with a tiny tune generated by
  the tests, so they need no network and store no music.
- `npm run lint` and `npm run format` run ESLint and Prettier.

## Layout

| Path | What it holds |
|---|---|
| `index.html` | The page: canvas, touch buttons and the information page. |
| `js/main.js` | Entry point: builds the world, wires up input, runs the frame loop. |
| `js/config.js` | Constants and all the game's text. |
| `js/state.js` | Shared game state (`G`), the player (`P`) and message helpers. |
| `js/world.js`, `js/worldview.js` | City generation and collision queries; drawing the map. |
| `js/cars.js`, `js/peds.js`, `js/player.js` | Car handling and AI, pedestrians and police on foot, Big Honk, the player. |
| `js/heat.js`, `js/missions.js`, `js/spawner.js`, `js/items.js` | Wanted level, jobs, populating the streets, bullets and pickups. |
| `js/game.js`, `js/render.js`, `js/input.js` | Per-frame update, drawing, keyboard and touch. |
| `js/endings.js` | The game-over and victory screens. |
| `js/icons.js` | Pixel-art icons for the touch-screen buttons. |
| `js/help.js`, `js/glyphs.js` | What the game says about its controls, for keyboards and for touch screens; the font's letter shapes. |
| `specs/` | The [game design](specs/design.md): the rules and the look, with the numbers, for every version including the Commodore 64 one. Feature specs: [playing on a phone](specs/touch-controls.md) lists every touch-screen requirement and the tests for each. |
| `assets/` | Picture files: the two end screens. |
| `js/screen.js`, `js/font.js`, `js/sprites.js`, `js/audio.js` | Canvas, bitmap font, sprites, sound effects and the built-in tune. |
| `js/figures.js` | People on foot as pixel art: passers-by, police, scooter riders, cultists and the player; and Big Honk, the goose. |
| `js/playlist.js`, `js/radio.js`, `js/info.js` | Playlist parsing, the radio, the information page. |
| `js/presence.js` | Optional Discord Rich Presence: tells the presence bridge what the game is doing. Off by default. |
| `terms.html`, `privacy.html` | Terms of use and privacy policy, linked from the game and from the Discord application. |
| `tools/presence-bridge/` | The presence bridge: a small Go program players can run to show the game on their Discord profile. See its README. |
| `sidplayer.js` | Bridge between the radio and the SID player. |
| `usbsid-player/` | USBSID-Player, the WebAssembly SID player. See its README. |
| `radio/` | The radio playlist. See its README for how to add tunes. |
| `tests/` | Unit tests, browser tests and a small static server. |

`world.js`, `playlist.js`, `cars.js` and the other game-logic modules do not touch the page when imported,
which is what lets the unit tests run them in Node.

## Discord Rich Presence

Players can choose to show what they are doing in the game on their Discord profile. A web page cannot talk
to Discord itself, so this needs the [presence bridge](tools/presence-bridge/), a small program the player runs
on their own computer. The setting is on the information page and is off by default; until a player switches
it on, the game makes no request to their computer. The bridge's README covers installing it, what it sends,
and its [code signing policy](tools/presence-bridge/CODE_SIGNING_POLICY.md).

## The repository

The game used to live in the `gta-c64/` folder of [mselin/mselin.github.io](https://github.com/mselin/mselin.github.io),
the homepage's repository, and moved here with its history on 20 November 2026. Its address did not change: a
repository's GitHub Pages site is served at `https://mselin.github.io/<repository>/`. The homepage and the
profile page link here.

**CI** ([`ci.yml`](.github/workflows/ci.yml)) runs on every pull request and every change to `main`:

| Job | What it checks |
|---|---|
| Site checks | The HTML pages are valid (`html-validate`). |
| Repository checks | [`check_repo.py`](.github/scripts/check_repo.py): JSON and SVG files parse, local links point at files that exist, and no private addresses or private terms. |
| Sleazeburg 64 tests | Lint, the unit tests, and the browser tests, these with the real presence bridge. |
| Presence bridge on Linux, Windows and macOS | `gofmt`, `go vet`, the tests (with the race detector on Linux) and the release builds. |
| Presence bridge builds are reproducible | The builds from all three systems are byte for byte the same. |
| Homebrew formula on macOS | The formula installs from this commit and passes its test. |
| Desktop app on Linux, Windows and macOS | `rustfmt`, `clippy`, the Rust tests and a build; on Linux, a smoke test of the real app. |
| All checks passed | The one check `main` requires: it passes only if every job above did. |

**Publishing:** after **All checks passed** on `main`, the **Publish the game** job puts the files the game
loads (the ones [`desktop/stage.mjs`](desktop/stage.mjs) lists) on GitHub Pages; the tests, tools and sources
are not published. The repository's Pages source is "GitHub Actions". The deploy step gets three tries, with a
wait between them, because GitHub's deploy action sometimes cannot find the page it was handed a moment before.

[`check_repo.py`](.github/scripts/check_repo.py) also reads an optional `PRIVATE_TERMS` repository secret:
host names, domains and similar, one per line, that must never appear in the repository. A match fails the
check and is reported by file and line only, never by the term itself, because Actions logs on a public
repository are public.

**Planning work:** features and implementation work are tracked as [issues](https://github.com/mselin/gta-c64/issues),
with a form for each: **Feature** (labelled `enhancement`) for something new or different in the game, and
**Implementation** (labelled `implementation`) for building, releasing, setting up or testing. A pull request
says which issue it closes ("Closes #12"). A change to the game's rules or look also updates
[`specs/design.md`](specs/design.md), which the Commodore 64 version follows.

**Making changes:** `main` takes changes only through pull requests, and only once **All checks passed** is
green. The actions in the workflows are pinned to exact commits, and Dependabot opens a pull request once a
month to update them.

**Releasing the presence bridge:** pushing a tag of the form `tools/presence-bridge/vX.Y.Z` starts
[`presence-bridge-release.yml`](.github/workflows/presence-bridge-release.yml). It tests on three systems,
builds the Linux and Windows binaries, checks the builds are reproducible, records where they were built, and
publishes the release. Version 0.1.0 was released from the homepage's repository, under the tag
`gta-c64/tools/presence-bridge/v0.1.0`; later versions are released here. The bridge's
[README](tools/presence-bridge/README.md) has the details.
